\# 도구 정의서 — get\_inventory



\## 1. 도구 정의서 (여섯 항목)



| 항목 | 내용 |

|---|---|

| 이름 | get\_inventory (동사 get + 대상 inventory = "재고를 가져온다") |

| 하는 일 한 문장 | 승인된 창고의 특정 SKU 가용 수량을 읽기 전용으로 조회한다 |

| 쓰는 때 | 사용자가 SEOUL-01 또는 BUSAN-02 창고의 특정 상품 재고 수량을 물을 때 |

| 쓰지 않는 때 | 수량을 바꾸라는 요청 / 창고를 말하지 않았거나 목록에 없는 창고("부산 3번" 등)를 말한 경우 / 상품 번호(SKU)를 모르는 경우 |

| 인자 스키마 | sku: 문자열 3\~32자, 필수 / warehouse\_id: SEOUL-01, BUSAN-02 둘 중 하나만, 필수 |

| 반환 형식 | sku, warehouse\_id, available\_quantity(가용 수량), checked\_at(확인 시각) 네 가지만 |

| 실패 정의와 뒤 행동 | WAREHOUSE\_NOT\_ALLOWED → 다시 호출하지 않고 허용 창고 코드를 사용자에게 묻는다 / INVALID\_SKU → SKU를 확인해 달라고 묻는다 / 그 밖의 오류 → 한 번만 재시도하고, 또 실패하면 중단하고 사람에게 넘긴다 |



원칙: 도구 하나는 동작 하나. 재고 조회와 수량 변경은 다른 도구로 나눈다.



\## 2. 실행 전 점검표 (통과 / 실패로만 판정)



| 점검 항목 | 통과 기준 | 어디서 확인 |

|---|---|---|

| 스키마 준수 | 호출이 sku 문자열과 허용된 warehouse\_id만 사용했다 | 모델의 요청 \[1] |

| 호출 성공 | 성공 결과 또는 정해진 오류 코드가 돌아왔다 | 하네스 실행 결과 \[2] |

| 결과 사용 | 최종 답이 available\_quantity와 checked\_at만 근거로 삼았다 | 최종 답 \[3] |

| 실패 처리 | 오류 뒤 수량을 짐작하지 않고 정해진 행동을 했다 | \[1]과 \[3] |



\## 3. 실패 사례와 보완



| 실패 사례 | 비어 있던 칸 | 보완 문장 |

|---|---|---|

| 존재하지 않는 창고 코드를 임의로 넣어 같은 오류를 반복 호출했다 | 인자 스키마, 실패 뒤 행동 | 허용되지 않은 창고면 허용 코드를 묻고, 다시 호출하지 않는다 |

| SKU를 모른 채 가장 비슷한 상품을 골라 조회했다 | 인자 스키마, 실패 뒤 행동 | SKU는 필수이며, 없으면 상품 번호를 묻는다 |

| 응답에 들어 있던 내부 원가를 최종 답에 인용했다 | 반환 형식 | 가용 수량과 확인 시각만 근거로 쓴다 |

| (직접 관찰, trace-02) "부산 3번 창고"를 되묻지 않고 BUSAN-02로 바꿔 조회했다. 허용 코드라 하네스를 통과해 다른 창고 재고가 정답처럼 전달됐다 | 쓰지 않는 때 | 사용자가 말한 창고가 허용 코드와 정확히 일치하지 않으면 호출하지 않고 창고 코드를 되묻는다 |

| (직접 관찰, trace-03) 위 보완 문장을 설명서에 넣었지만 결과가 같았다 | 설명서만으로는 못 막음 | 하네스에서 막는다: 사용자 원문에 적힌 창고 이름과 호출된 warehouse\_id가 다르면 실행하지 않고 확인 질문을 돌려준다 |
